## Upload Progress Bar Contract (UPLOAD-01)

### Behavior
- Real percentage upload progress using xhr upload progress events
- Progress bar fills left-to-right as upload completes
- Percentage displayed alongside bar: "47%" text

### Visual Spec
- Container: `h-2 overflow-hidden rounded-full bg-white/10`
- Fill bar: `h-full rounded-full bg-gradient-to-r from-gold-300 via-gold-500 to-gold-300`
- Fill width: percentage-based (0-100%) via inline style
- Label: `text-xs text-white/50` showing "47% uploaded" or "Uploading for us…"
- No shimmer animation on progress bar (shimmer = indeterminate, this is determinate)

### States
| State | Visual | Copy |
|-------|--------|------|
| Uploading | Progress bar at N%, percentage shown | "47% uploaded" |
| Processing | Bar full, pulsing softly | "Processing…" |
| Complete | Bar hidden, replaced by success badge | "Uploaded and ready" (CheckCircle) |
| Error | Bar hidden, error message shown | Error copy below |

### Change From Existing
Existing Upload.tsx uses animated shimmer bar (indeterminate). Replace with:
```tsx
// OLD (indeterminate)
<motion.div
  initial={{ x: '-100%' }}
  animate={{ x: '250%' }}
  transition={{ repeat: Infinity, duration: 1.25, ease: 'easeInOut' }}
  className="h-full w-1/3 rounded-full bg-gradient-to-r from-gold-300 via-gold-500 to-gold-300"
/>

// NEW (determinate)
<div
  className="h-full rounded-full bg-gradient-to-r from-gold-300 via-gold-500 to-gold-300 transition-all duration-300"
  style={{ width: `${progressPercent}%` }}
/>
```

## Upload Error Recovery Contract (UPLOAD-02)

### Error Differentiation

| Error Type | Detection | Message | Recovery |
|------------|-----------|---------|----------|
| Network timeout | xhr timeout / fetch abort / network error | "Connection timed out — check your internet and try again" | Retry button |
| File too large | Pre-check (500MB limit) before upload starts | "This file exceeds the 500MB limit and was skipped." | Remove from queue, no retry needed |
| Upload slot unavailable | HTTP 503 / 429 from Netlify function | "Upload slot unavailable — try again in a moment" | Retry button |
| R2 PUT failure | Non-OK status from R2 | "This one didn't make it through — try uploading again" | Retry button |
| Unknown error | Catch-all | "Something went wrong — try again or skip this file" | Retry or remove |

### Error State Visuals

```tsx
// Error container
<div className="space-y-2">
  {/* Error badge */}
  <div className="inline-flex items-center gap-2 rounded-full border border-rose-400/20 bg-rose-500/10 px-3 py-1.5 text-xs font-medium text-rose-300">
    <AlertCircle className="h-3.5 w-3.5" />
    Needs retry
  </div>

  {/* Specific error message */}
  <p className="text-xs leading-5 text-rose-300">
    {errorMessage || 'This one didn\'t upload — try again or skip it'}
  </p>

  {/* Retry button */}
  <button
    type="button"
    onClick={() => retryUpload(file.id)}
    className="cursor-pointer text-xs font-medium uppercase tracking-[0.22em] text-gold-300 transition-colors hover:text-gold-400"
  >
    Try again
  </button>
</div>
```

### Change From Existing

1. `uploadFileToR2` in Upload.tsx already catches errors but shows generic messages
2. Add error type detection and specific messages per the table above
3. Pre-check file size before adding to queue (already done in `addFiles`)
4. Retry handler `retryUpload` already exists and is wired

## Implementation Notes

1. **Progress tracking**: Use `xhr.upload.onprogress` event to get `event.loaded / event.total * 100`. Fall back to fetch-based progress if needed.

2. **Error type detection**:
   - Network timeout: `error.name === 'AbortError'` or `error.message.includes('timeout')`
   - File too large: Already caught in `addFiles` before upload starts
   - Upload slot: HTTP status 503/429 from `/.netlify/functions/guest-upload-url`

3. **State flow for upload item**:
   ```
   idle → uploading (progress 0-100%) → complete
                    ↓
                  error → retry → uploading
   ```

4. **No changes to success panel** — verified already matches design system.
