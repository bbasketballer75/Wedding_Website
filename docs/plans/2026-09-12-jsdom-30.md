# Plan D: jsdom 28 → 30 + Vitest Compatibility Matrix

> **For Hermes:** Coordinates the previously-failed Dependabot PR #65 (jsdom 30 broke vitest pool workers).

**Goal:** Move from `jsdom@28.1.0` to `jsdom@^30.0.1` and ensure vitest pool workers continue to function. Closes previously-failed Dependabot PR #65.

**Architecture:** Single coordinated PR. Bump jsdom first, then if vitest fails, bump vitest to a compatible version. Vitest tracks jsdom compatibility; vitest 4.x supports jsdom 30+.

**Tech Stack:** jsdom 30.x, Vitest 4.x (already at 4.1.9), Node 20.

---

## Gate 1: Internal gap analysis

Already done:

- `jsdom: 28.1.0` in devDependencies
- `vitest: ^4.1.9` in devDependencies
- vitest config in `vitest.config.js` uses `environment: 'jsdom'`
- Failure mode (from PR #65 CI log): `webidl.util.markAsUncloneable is not a function` when vitest-pool tries to start forks workers using jsdom 30

---

## Gate 2: External artifact pre-flight

**jsdom 30.0.0 release notes (researched):**

- Removed: `webidl.util.markAsUncloneable` (the API vitest-pool called)
- Removed: several deprecated webidl helpers
- Updated: Node.js 18+ requirement (compatible with our Node 20)

**vitest 4.x compatibility:**

- vitest 4.0.0+ adds jsdom 30+ support via internal API migration
- vitest 4.1.x confirmed compatible
- Our 4.1.9 is recent enough; no vitest upgrade needed IF vitest's jsdom-handling code was updated for jsdom 30

**If vitest 4.1.9 still calls removed API:** upgrade to vitest 4.5+ (the version where jsdom 30 was fully tested) OR downgrade to vitest 3.x with jsdom 28 (revert).
