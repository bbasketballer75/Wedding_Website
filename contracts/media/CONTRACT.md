# Media Contract — origin, delivery, and the no-media-loss invariant

Status: generated by backend-eng for Wave 0 (2026-11-08) from the frozen legacy source. Read-only
description of how media is stored and served today; the rebuild may change implementation but not
the bytes, paths, or access rules. Machine-readable companion: [`INVENTORY.json`](./INVENTORY.json).

Measured on the frozen checkout (`rebuild/greenfield` @ `legacy-freeze-2026-11-08`).

## 1. Who owns which bytes

| App host        | Netlify static `dist/`                                                                                                                            | SPA bundle, `public/images/**` (tracked photography used by pages), `public/icons`, favicons, `_headers`, `offline.html`                          | build only                                   |

| Legacy Storage  | `guest-photos`, `guest-videos`, `guest-voice`                                                                                                     | policies exist; bucket rows are not created by migrations; unused by current flow                                                                 | n/a — drift                                  |
| Serverless      | `netlify/functions/guest-upload-url.ts` (R2 presign), `download-pack.ts` (zip proxy), `netlify/edge-functions/gallery-share.ts` (OG meta rewrite) | —                                                                                                                                                 | —                                            |

Two distinct roles must not be conflated:

- **R2/CDN** is the production media origin for anything referenced by `getMediaPath()` with an
  offload prefix. Bytes are public and cacheable for a year.
- **Supabase Storage** is only for private admin artifacts (`media-review-artifacts`) plus legacy
  guest buckets whose policies survive in migrations. It is _not_ the media origin for the archive.

## 3. `getMediaPath()` offload rules (`src/utils/media.ts`)

```ts
export function getMediaPath(path: string): string {
  if (/^https?:\/\//.test(path)) return path // absolute URLs pass through untouched
  const normalizedPath = path.startsWith('/') ? path : `/${path}`
  const mediaBaseUrl = trimTrailingSlash(import.meta.env.VITE_MEDIA_BASE_URL || '')
  const shouldOffload = OFFLOADED_MEDIA_PREFIXES.some(prefix => normalizedPath.startsWith(prefix))
  if (!mediaBaseUrl || !shouldOffload) return normalizedPath
  if (import.meta.env.DEV) return `/__media_proxy/${toRemoteMediaPath(normalizedPath)}`
  return `${mediaBaseUrl}/${toRemoteMediaPath(normalizedPath)}`
}
```

Rules that must survive the rebuild:

1. Only `/video/`, `/background_audio/`, `/media/` are offloaded. `/images/` stays local.
2. With `VITE_MEDIA_BASE_URL` **unset**, everything resolves to the same-origin path (local dev
   without CDN, and parity builds that must not touch the network).
3. In `DEV`, offload resolves to the `/__media_proxy/*` Vite proxy (`vite.config.js` `server.proxy`),
   which rewrites to the CDN base URL with `changeOrigin`.
4. Path segments are **never sanitized** — `toRemoteMediaPath()` only strips the leading slash and
   collapses empty segments, so the literal `+` in `Bach+ette` and `%20` in `Guest Uploads` reach the
   Worker intact. Re-encoding or URL-decoding these breaks CDN lookups (historical production bug).
5. Absolute `http(s)://` URLs are returned unchanged (used for guest uploads that already point at R2).
6. `getAbsoluteMediaUrl(path) = getAbsoluteUrl(getMediaPath(path))` — used for OG images; `VITE_SITE_URL`
   supplies the origin.

Build-time companion: `scripts/prune-local-media.js` (postbuild) deletes `dist/video`,
`dist/background_audio`, `dist/media` when `VITE_MEDIA_BASE_URL` is set, so heavy media never ships in
`dist/`. `vite preview` also proxies `/media` → `VITE_MEDIA_BASE_URL` for local preview of production
behaviour.

## 4. CORS and cache headers (the delivery contract)

Worker `src/workers/media-rewrite/index.ts`:

- Allowed origins (echoed in `Access-Control-Allow-Origin`, plus `Vary: Origin`): `https://www.theporadas.com`,
  `https://theporadas.com`, `https://wedding.theporadas.com`, `http://localhost:{5173,4173}`,
  `http://127.0.0.1:{5173,4173,4174}`.
- Methods: `GET, HEAD, OPTIONS` (`405` otherwise; `OPTIONS` → `204`).
- Allowed request headers: `Range, Content-Type, If-None-Match, If-Modified-Since`.
- Exposed response headers: `Accept-Ranges, Content-Length, Content-Range, Content-Type, ETag`.
- `Access-Control-Max-Age: 86400`.
- Success: `Cache-Control: public, max-age=31536000, immutable`, `Accept-Ranges: bytes`, `ETag`
  (`object.httpEtag`), real `Content-Type` from R2 metadata; conditional GET honoured with `412`.
- Range: `206` + `Content-Range: bytes start-end/size` + exact `Content-Length`; suffix ranges supported.
- Errors: `404` with `Not Found: <key>` (a missing key is a hard 404, never a fallback page file).

Netlify `public/_headers` (app origin):

- Global security headers: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, HSTS, CSP.
- CSP allowlist includes `https://*.supabase.co`, `https://media.wedding.theporadas.com`,
  `https://*.r2.dev`, GA and Sentry ingest in `connect-src`, and `media-src 'self' data: blob: https:`.
  Dropping the media host from `connect-src` breaks lightbox CORS fetches and caption tracks.
- `/assets/*` → `Cache-Control: public, max-age=31536000, immutable`; `sw.js`, `registerSW.js`,
  `manifest.webmanifest`, `robots.txt`, `sitemap.xml` → `no-cache, no-store, must-revalidate`.

Service worker runtime caching (`vite.config.js` Workbox):

- `/media/_thumbs/**` → `CacheFirst` cache `gallery-images-v2`, maxEntries 500, 30 days,
  `cacheableResponse.statuses: [200]` only.
- `/media/**` (non-thumbs) → `CacheFirst` cache `gallery-direct-media-v2`, maxEntries 300, 30 days,
  statuses `[200]` only.
- Status `0` (opaque) must never be cached here: `<img>` no-cors responses are opaque and serving one
  to a later CORS `fetch()` breaks the lightbox (`net::ERR_FAILED`); this is a hard-won invariant.

Live verification of the CDN half (read-only, opt-in):
`tests/e2e-live/media-cors-contract.spec.ts` (`E2E_LIVE_MEDIA_CORS=1 npm run test:live:media-cors`)
asserts for `https://media.wedding.theporadas.com/video/main.vtt`: status 200/206, `Content-Type:
text/vtt`, `Access-Control-Allow-Origin` = site origin or `*`, `Accept-Ranges: bytes`,
`Cache-Control: max-age=…`, `Vary: Origin`, and `Content-Range`/`Content-Length` correctness on 206.
The public e2e suite only mocks this contract (`tests/e2e/support/publicSite.ts`); it cannot prove the
CDN still behaves.

## 5. Guest upload media path (write contract)

`netlify/functions/guest-upload-url.ts` (POST only):

- Requires server-only env: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`,
  `R2_MEDIA_BUCKET` (default `wedding-media`), `R2_PUBLIC_BASE_URL` (default
  `https://media.wedding.theporadas.com`). Never exposed to the browser.
- Allowed MIME: `image/jpeg|png|webp|heic|heif|gif`, `video/mp4|quicktime|webm`; max 500 MB
  (client validates the same cap).
- Object key: `guest-uploads/{photos|videos}/<uuid>.<ext>`; ext normalised (`jpeg→jpg`, `quicktime→mov`).
- Returns `{ uploadUrl (presigned PUT, 300 s), publicUrl }`; the browser PUTs directly to R2, then
  inserts a `guest_uploads` row (`photo_urls`/`video_urls` hold the public URLs; fingerprints ride in
  `photo_fingerprints`/`video_fingerprints`).
- Moderation: `guest_uploads.status` starts `pending`; admin approval is required before the row is
  public (RLS `Allow public read approved`). Publishing to the gallery copies URLs into `photos`
  (see `publishGuestUploadPhotosToAlbum()`), which is how an approved upload appears in an album.
- `netlify/functions/download-pack.ts` zips up to 50 photos by fetching each `download_url || url`
  server-side and returning `theporadas-photos.zip`; a rebuild must keep original-download serving.

## 7. The no-media-loss invariant

**Definition.** After cutover, every media asset reachable today is still reachable:
(a) every URL in `contracts/content/MEDIA_MANIFEST.json` resolves;
(b) every `photos.url`, `photos.thumbnail`, `photos.download_url`, `guest_uploads.photo_urls`,
`guest_uploads.video_urls`, `site_editorial_features.source_url`, `guestbook_messages.media_url`,
`media_review_batches.artifact_paths` value still resolves;
(c) original downloads still return the original bytes (zip download packs, lightbox "download original");
(d) captions (`.vtt`) still return `text/vtt` over CORS, and video still supports Range/206;
(e) the R2 object population is unchanged (same keys, same ETags or a recorded checksum manifest).

**How it is proven.** Wave 0 records the local inventory above and the DB-side URL columns; Wave 9
cutover must compare them against a read-only listing of the R2 bucket + the production DB:

1. Produce a manifest of all media URLs referenced by content/contracts and by the DB
   (`photos.*`, `guest_uploads.*`, `guestbook_messages.media_url`, editorial `source_url`).
2. `HEAD` each distinct CDN URL read-only, recording status + `Content-Length` + `ETag`; any non-200
   (or content-length mismatch for originals) is a media-loss failure.
3. Re-run the checks against the rebuilt app before retiring the legacy deploy; keep the legacy
   `dist/` and R2 bucket read-only for one full checkpoint window as rollback.
4. Add the manifest to CI so a future deletion of a referenced path fails the build (the contract
   already anticipates this with `MEDIA_MANIFEST.json`).

**Known gaps for wave 9.** R2 bucket population is not enumerated yet (no production credentials in
Wave 0, and the rules forbid production writes; a read-only listing with an owner-provided key is the
expected mechanism). `media-review-artifacts` object list can only be read with the service role.
The Service-Worker cached population is device-local and not part of the invariant.

## 8. Drift notes

- Runtime media lookup assumes the Worker mapping is exactly as documented; any Worker change is a
  production change and must be versioned in the rebuild's infra contract.
- `wedding-gallery` storage bucket + `wedding_gallery`/`gallery_categories` tables are referenced only
  by dead legacy code (`src/services/galleryService.ts`, nothing imports it) and do not exist in the
  31 migrations; they are intentionally absent from the rebuild data layer.
- Supabase Storage legacy buckets `guest-photos`/`guest-videos`/`guest-voice` have policies from
  migrations but no bucket rows after a clean reset; the rebuild should not recreate them.
